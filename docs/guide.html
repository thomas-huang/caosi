caosi

在你自己的电脑上跑的轻量 CLI。Claude Code、Codex、Gemini CLI 可以继续说自己的协议；caosi 按名字转到你配置的上游，必要时做协议转换。

默认入口

http://127.0.0.1:9999/{provider_name}

只绑 loopback。配置在 ~/.caosi/providers.jsonc。

60 秒上手

  1. 编译并第一次运行（会写样例然后退出，这是故意的）： 
    go build -o caosi ./cmd/caosi
./caosi
  2. 打开 ~/.caosi/providers.jsonc，把 api_key 换成真密钥。用 Claude Code 打 OpenAI 兼容上游时，务必保留 model（例如 deepseek-chat），否则上游会看到 claude-* 而 400。
  3. 再运行 ./caosi。看到「正在监听」之后： 
    curl -s http://127.0.0.1:9999/health

怎么配一条 Provider

文件是 JSONC（可以写 // 注释）。key 就是 URL 里的名字。

{
  "deepseek": {
    "base_url": "https://api.deepseek.com",
    "protocol": "openai_chat",
    "api_key": "sk-...",
    // "model": "deepseek-chat"
  }
}
protocol上游说话方式
openai_chatOpenAI Chat Completions
openai_responsesOpenAI Responses
claude_messagesClaude Messages
geminiGemini generateContent

model 可选：填了就改写客户端带来的模型名。headers 可选，用来补 OpenRouter 之类的额外头。

base_url 是前缀，caosi 不会自作聪明地剥 /v1。写成上游真正要接的根，例如 DeepSeek 用 https://api.deepseek.com。

把客户端指过来

把 Base URL 设成 http://127.0.0.1:9999/deepseek（换成你的 Provider Name）。客户端密钥可以随便填，caosi 不会把它转到上游，只用配置里的 api_key。

Claude Code

export ANTHROPIC_BASE_URL=http://127.0.0.1:9999/deepseek
export ANTHROPIC_API_KEY=dummy
claude

Claude Code 会打 /v1/messages。上游无论是 Chat、Responses 还是 Gemini，caosi 都会转成对应协议。

OpenAI SDK / Chat Completions 客户端

export OPENAI_BASE_URL=http://127.0.0.1:9999/deepseek/v1
export OPENAI_API_KEY=dummy

走 /v1/chat/completions 或 Codex 的 /v1/responses。和上游协议相同则透传；不同则转换（例如 Codex → DeepSeek Chat）。

Gemini CLI

# 把 API base 指到 http://127.0.0.1:9999/{provider_name}
# 请求路径仍是 :generateContent

Gemini 客户端可以打 OpenAI / Claude / Gemini 上游。同协议透传，跨协议会转换。

这一版能做什么

  • 同协议透传（body 不改，除非配了 model）
  • OpenAI Chat、OpenAI Responses、Claude Messages、Gemini 之间互相转换（含流式）
  • 文本、system、tools、thinking/reasoning、消息里的图片块按 Conversion Contract 映射
  • 改 providers.jsonc 会热加载；坏文件保留上一份可用配置
  • 注入 api_key / headers，丢掉客户端自带的密钥头
  • 只绑 127.0.0.1，端口默认 9999，可用 --port / --config-dir

caosi 不做 Web UI、OAuth、故障转移或接管客户端配置。

下一步建议

  1. 用 curl /health 确认进程活着。
  2. 先配一条你已经有密钥的 OpenAI 兼容端点（DeepSeek / OpenRouter / 本地 vLLM）。
  3. 用 Claude Code 对它发一句「只回 ok」，看终端里的请求日志，类似：deepseek claude_messages→openai_chat conversion 200 1ms。
  4. 也可以先不接 Claude Code，直接： 
    curl -s http://127.0.0.1:9999/deepseek/v1/messages \
  -H 'content-type: application/json' \
  -d '{"model":"claude-opus","max_tokens":16,"messages":[{"role":"user","content":"只回 ok"}]}'
  5. 同一条 Provider，再用 OpenAI 客户端打 /v1/chat/completions，日志应是 passthrough。
  6. 若 401：密钥或 base_url 不对，不是协议问题。若路径变成 /v1/v1/...：把 base_url 末尾的 /v1 拿掉。

常用命令

./caosi --help
./caosi --port 9999 --config-dir ~/.caosi --log-level info

日志打在 stderr，一行一条，不含请求/响应 body。

caosi 不是网关管理器：没有 Web UI、没有 OAuth、不会改你的 Claude Code 配置文件。
